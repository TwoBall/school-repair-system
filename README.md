## 2. 二维码：请一律做成「活码」

三个入口码与各场所报修码都通过**草料二维码的活码**生成：扫码 → 草料短链 → 跳转目标页。

- 换域名、改路径、改房间号时，**只需在草料后台改跳转地址**，已张贴的纸质码一张都不用重贴。
- 场所报修码指向 `https://bx.600918.xyz/?bldg=<楼栋>&room=<房间>`，扫码后报修页会提示「已按扫码位置带入：C6 学生宿舍 · 305教室」。
- 楼栋字典改过之后旧码会失效，但**不会静默失败**——页面明确提示「该楼栋不在当前可选楼栋中，请手动选择」，房间照常带入。
- 总务处入口的码等同完整管理权限，**只在总务处内部流转，不要与报修码一起贴在公共区域**。

## 3. 业务配置

### 楼栋字典（16 条，编号 + 用途）

`A1–A4 教学楼`、`B1–B2 实训楼`、`C1–C8 宿舍`（C7 为教师宿舍）、`D区 行政办公楼`、`室外公共区域`

字母即楼群类别：**A=教学楼、B=实训楼、C=宿舍、D=行政区**，按历史 7051 条工单的地点分布归纳排序。后台 → 基础数据 → 楼栋 可增删改。

> 已上线的库会在下次访问时自动迁移：仅当字典仍是内置旧值（教学楼A栋 / 学生公寓1栋…）时才替换，**你已自行改过的字典不会被覆盖**。
> 楼栋改名**不回溯历史工单**（工单存的是名称快照），这是有意为之。

### 工单耗材字段

工单新增 `material`（耗材/配件）与 `materialSource`（配件购方）两列，师傅完工时与结果说明一并填写，均选填、纯自由文本。

流向：时间轴 note → Webhook 完工推送 → 管理端工单详情 → 打印存档（完工后打印才出现该行）→ 导出 CSV 第 14–15 列（共 18 列）。**不对报修人展示**。

## 5. 部署到 Cloudflare Pages（首次搭建或重建时用）

1. **创建 Pages 应用**：Workers 和 Pages → 创建 → Pages → 连接到 Git → 选仓库 `TwoBall/school-repair-system`。构建参数：分支 **`cloudflare-pages`**、预设 `Vite`、构建命令 `npm run build`、输出目录 `dist`。
2. **建 D1 并绑定**：存储 → D1 → 创建 `school-repair-db` → 回到 Pages 项目 → 设置 → 函数 → D1 绑定，变量名必须为大写的 **`DB`**。
3. **建 R2 并绑定**：存储 → R2 → 创建 `school-repair-photos` → 同处添加 R2 绑定，变量名 **`PHOTOS`**。
4. **重新部署**：部署页 → 重新部署。首次打开页面时系统会**自动建表并填充种子数据**。

> 生产分支保持 `cloudflare-pages`。本分支（`ui-ux-optimization`）的改动尚未归并进去，别直接切生产分支。

## 7. 本地开发

```bash
npm install
npm run dev      # /api 代理到 http://localhost:3000
npm run build    # 产出到 dist/
npm run preview  # 预览构建产物
```

### 开发约定（改前端前先读一遍）

1. **交互原语只在 `src/common/utils.js` 实现一次**，三端引用，不要在各端重写。
2. **异步按钮一律用 `runAction()`**，禁止手写 `btn.disabled`。
3. **列表视图一律配 `createPoller` + 错误态重试**，`silent` 刷新失败必须保持原界面不动。
4. **新增 `data-act` 必须同时补进 `delegateActions` 映射**。
5. **骨架屏样式不能依赖 design token**（CSS 由 JS 注入、加载更晚），需自带变量。
6. **新增动效必须被 `prefers-reduced-motion` 兜住**；注意伪元素不受全局 `*` 规则约束。
7. **字典类常量改两处**：后端 `functions/api/[[route]].js` 与前端 `src/reporter/main.js` 的兜底副本。
8. **一键填入的卡片与弹窗 chips 不要混用**：卡片 `.tpl-card`（表单）+ 全宽虚线入口 `.tpl-all`，弹窗里才是 `.tpl-chip`。

### 回归验证方法

- 无法做视觉验证时用 **jsdom** 跑 DOM 交互回归：先用 vite lib mode 把入口打成 IIFE（`formats: ['iife']`），再注入 jsdom 驱动点击。
- 建表 / 迁移类改动用 **Python `sqlite3`** 在真实 SQLite 上跑「全新库 / 老库 / 用户已改字典」三个场景。
